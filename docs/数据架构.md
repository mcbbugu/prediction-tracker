# 数据架构（2026-10-23 定稿）

一句话：**把「某人说过什么、后来怎样」变成任何人都能独立复核、无法事后篡改、随时间自动增值的证据账本。**

代码可以被复制，但时间戳、存档和积累下来的账本不能。下面五层逐层叠加，每层单独就有用。

---

## 第 1 层：内容寻址的证据仓库（已有雏形）

- 每个存档网页、每段提取文本、每次模型调用的输入和输出，都用 SHA-256 作为 id 存一份，内容不变 id 就不变。
- 主张、判定、利益关系不直接存文字，只引用这些 id。
- **可验证**：任何人拿到原始字节，重算哈希就能确认我们没有改过。

已经做到：网页原始字节、SHA-256、抓取途径。
还缺：模型调用的输入输出也要内容寻址（见第 2 层）。

## 第 2 层：可重放的流水线

- 流水线拆成纯步骤：`识别 → 发现 → 存档 → 抽取 → 结构化 → 核对 → 判定`。每一步的输入是上一步产物的哈希，输出也存成哈希。
- 每次模型调用记录：模型名、版本、提示词哈希、参数、输出哈希。
- **重放**：用同样的输入和缓存的模型输出，重跑必须得到逐字节相同的结果。这条写成测试。
- **对比**：换模型或改提示词后重跑，自动产出一份差异报告：哪些主张新增、消失、改判。流水线升级从此有据可查。
- **复用**：同一网页被多个人物、多条判定引用时只存一次、只抽取一次；同一步骤在按需分析、批量建库、到期核对三条流程里共用。

## 第 3 层：可检验命题（核心创造点）

现在一条主张是一句原话加一个期限。我们把它再结构化成**可机器判定的命题**：

```
主体：Tesla
指标：FSD 无人监管商用（城市数 ≥ 1）
阈值：≥ 1
期限：2025-12-31
判定来源：[监管文件 / 公司公告 / 指定数据源]
判定方式：structured（数据源直接判） | model（模型读证据判）
```

- 能落到结构化数据上的命题（营收、股价、发布日期、用户数、监管批文），由**确定性判定器**直接判：读 SEC XBRL、股价接口、官方公告，不经过模型，结果可以 100% 复现。
- 剩下的才交给模型判，并走 010 的双模型交叉判定。
- 命题在**收录时**就写好判定标准，不等到期再定，避免事后挑对自己有利的标准。这是预测市场（Metaculus、Polymarket）的「判定细则」做法，用在公众人物身上。
- 方法页公开：确定性判定占比多少、模型判定占比多少。这个比例应该逐步上升。

## 第 4 层：透明日志（不可篡改、不可复制）

- 所有新增和修改（新主张、改判、作废、更正）按时间追加进一个只增不改的日志，每条记录包含上一条的哈希，形成哈希链（与证书透明度 Certificate Transparency、Sigstore 是同一类思路）。
- 每天把当天的根哈希公开发布：写进公开 git 仓库的一次提交，并提交 Wayback 存档。
- **可验证**：任何人都能证明「先验在 2026-10-23 就收录了这句预测，之后没有偷偷改过」。
- **不可复制**：别人今天抄走全部代码和数据，也没法证明自己在结果出来之前就收录了。时间本身就是护城河，越早开始越值钱。

## 第 5 层：评测台

- 金标准集：人工核对过的样本（包括校准盲标的结果）。每次流水线升级，自动跑一遍并给出：
  - 发现召回率：已知的预测找到了多少
  - 抽取精度：抽出来的有多少是真的带期限的预测
  - 判定一致率、区间下界
  - 单位成本：每条有效主张花了多少次搜索、多少秒
- 每个流水线版本的指标在方法页公开，形成版本历史。
- 低于上一版的指标不允许上线（CI 卡住）。

## 解决「找不到数据」（第 2 层的发现步骤）

现在发现只靠联网搜索，所以产出低（例：陆奇 563 秒、6 次搜索、0 条主张）。改成多源发现，免费、结构化的来源优先：

1. **结构化一手来源**（不消耗 AFP）：SEC 8-K 和财报电话会文字稿、公司新闻稿 RSS、YouTube 字幕（采访、发布会）、播客文字稿、个人博客和 RSS。
2. **已有存档反向挖掘**：库里已存的网页里提到的其他人的预测，顺手抽出来。
3. **联网搜索**只用来补缺，搜索词由前两步的线索生成，不再盲搜。
4. 每个来源单独统计产出率（有效主张数 ÷ 成本），产出率低的自动降低优先级。
