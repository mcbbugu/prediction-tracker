# 039 YouTube 字幕：核实说话人，原始字幕单独存档

负责人：Cursor
优先级：P0
关联 issue：#13

## 问题（已核对属实）

- `api/src/claims/sources/youtube-captions.ts:81` 只要求视频标题里有这个人的名字。`parseVtt()` 把主持人、嘉宾、旁白的字幕合成一段，去掉了说话人和时间戳。`discover.ts` 的硬校验只检查「引文在页面里」「页面里有人名」，而标题已经满足人名这一条。所以主持人说的话可能被当成嘉宾的直接原话发布。
- 第 100 行 `bytes` 用的是清洗后的纯文本，`contentType` 却写成 `text/vtt`。哈希没法用来复核原始字幕。

## 做法

1. **归属**：
   - 字幕有说话人标签（VTT 的 `<v 说话人>` 或人工字幕的说话人标注）：只把目标人物的片段送去抽取，每条主张记下片段的起止时间戳。
   - 没有说话人标签（大多数自动字幕都是这样）：**只作为发现线索**，不直接生成主张。用里面的线索（产品名、年份、原话片段）去找文字报道或文字实录，再按普通网页流程核对。
   - 程序层面加硬约束：来源类型是混合字幕、且没有核实过说话人的，`keepVerified` 一律不予通过。
2. **存档**：原始 VTT 字节单独存一份，`content_type = text/vtt`，哈希就是原文件的。清洗后的检索正文另存，标 `text/plain` 并关联到原件。记录语言、自动或人工字幕、视频网址、抓取方式。
3. **排查**：列出已入库、来自 YouTube 字幕的主张，标出归属不明的，把 `publication` 改回 `proposed` 并写 `claim_events`，不删行，然后重算分数。
4. **测试**：标题有嘉宾名但预测是主持人说的；双方都有预测；没有说话人标签；自动字幕；逐字核对能通过但归属不明。以上情况都不能发布成嘉宾的原话。

## 范围

- `api/src/claims/sources/youtube-captions.ts`、`api/src/claims/sources/index.ts`、`api/src/claims/discover.ts`（只加硬约束）、`api/src/evidence/sources.ts`（如需关联两份存档）
- 新建排查脚本 `api/src/tools/audit-youtube-claims.ts`、测试文件
