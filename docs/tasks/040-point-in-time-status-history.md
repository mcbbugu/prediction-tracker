# 040 严格时点：从历史事件还原当时的判定，而不是用当前状态

负责人：Cursor
优先级：P1（现在的数据还不受影响，031 前瞻实验开始积累以后会受影响）
关联 issue：#8（第 4 条评论）

## 问题（已核对属实）

`api/src/queries/point-in-time.ts:51` 的 `judgedAtMap()` 取一条主张所有判定事件中**最晚**的时间。`claimAt()` 再结合主张**当前**的状态和证据：如果最晚一次判定在 T 之后，就把 T 时的状态退回成「待定」。

反例：2024-03 判为已兑现，2025-06 因为反证改判为部分兑现，T = 2024-12。严格模式应该返回 T 时的「已兑现」和当时的证据，实际却返回「待定」。这不会带进未来信息，但会丢掉当时确实已经知道的结论。`eventsByClaim()` 算 `verdict_tiers` 时也没有按 T 过滤。

说明：目前所有判定都写入于 2026-10-21 之后，现有数据暂不受影响。但改判、反证重判会越来越多，031 前瞻实验也要依赖严格模式，所以要在数据积累前修好。

## 做法

1. 从 `claim_events` 里取 T 之前**最后一个写状态的事件**，用它记录的状态（事件里的 `after.status` 或等价字段）还原当时的状态。如果事件里没记状态，先补上，让以后的判定、改判事件都带上前后状态。
2. 证据同样按时间还原：只保留 T 之前加入、且 T 时还没被替换的证据。还原不了的，这条主张在严格模式下标「不可用」，不参与计分，并计数报告。
3. `verdict_tiers` 只统计 T 之前的事件。
4. 测试：多次判定；反证改判；证据替换；事件正好落在 T 当天、前一天、后一天。
