# 037 下游评测：时点一致的先验 + 证据分量表修复

负责人：Cursor
优先级：P0（031 依赖它）
关联 issue：#8、#9、#3

## 问题（已核对属实）

1. **#8 未来信息泄露**：`api/src/queries/prior.ts` 的 `as_of` 只按说话日和期限筛选主张，判定结果用的是今天查到的（第 180 行 note 也这么写）。第 154 行起的 `latestDelay(person.id)` 和 `consistency_pairs` 都没有按 `as_of` 过滤。`downstream-eval.ts` 却把这份 JSON 告诉 B 组是「说话当天可查到的先验」。所以 030 的 B 组可能拿到了说话日之后才知道的信息。
2. **#9 量表截断**：`api/src/tools/downstream-eval.ts:128` 用 `clampProbability`（夹在 0..1）解析 0/1/2 分的证据分，2 分被截成 1。030 报告里的证据分均值不能按 0–2 理解。

## 做法

1. **不改面向用户的 `/v1/prior` 语义**（「站在那天看，结果按今天查到的判定」对普通读者是合理的），但在返回里把这层意思写得更明确：`as_of_semantics: "retrospective"`。
2. **新增严格时点模式**，只给评测用：`/v1/prior?...&as_of=T&strict=1`（或内部函数 `priorPointInTime`）。
   - 只计在 T 之前**已经判定**的主张：判定时间取 `claim_events` 里判定写入的时间；拿不准的一律排除。
   - 证据只用 T 之前发布或抓取的（证据缺少日期的排除）。
   - 延迟系数、可信度都按 T 截面重算，不用当前的快照表。
   - 说明：现阶段大部分判定都写入于 2026-10，严格模式下历史题的先验多半是「样本不足」。这是真实情况，照实报告。
3. `downstream-eval.ts` 的 B 组改用严格模式；提示词里的「说话当天可查到的先验」只在严格模式下使用。
4. **#9**：证据分单独解析为 0..2 的整数（越界、非法值记 null 并计数），概率仍夹在 0..1。加单元测试，覆盖 0、1、2、越界、字符串和非法值。
5. 重跑 030 的无泄露题。报告里标明：旧版的证据分和 B 组 Brier 与新版不可直接比较；在新版结果出来之前，030 的结论只算探索性的。
6. 加 fixture 测试：T 之后才判定的主张、T 之后的一致性对照、T 之后的兑现事件，都不能出现在严格模式的返回里。
