# 013 多源发现：提高产出率

负责人：Cursor
优先级：P0

## 目标

数据架构「解决找不到数据」：不再只靠联网搜索，提高每个人物的有效主张数。

## 背景

005 实测：陆奇 563 秒、6 次搜索、0 条主张；003 里 34 人中 12 人 0 条。发现步骤在 `api/src/claims/discover.ts`。

## 做法

1. 发现改为「来源适配器」：`api/src/claims/sources/<名字>.ts`，统一接口 `find(person) → 候选文档[]`，每个文档照存档标准存原始字节。先做：
   - `sec_transcripts`：此人任职上市公司的 8-K 新闻稿和财报相关附件（复用 SEC 代码，免费）。
   - `youtube_captions`：搜此人的采访和发布会视频，取公开字幕（用 yt-dlp 只下字幕，不下视频；本机没有就跳过并记录）。
   - `rss`：此人个人博客、公司新闻室的 RSS。
   - `web_search`：现有的联网搜索，放到最后，搜索词用前面来源里出现的线索（产品名、年份）生成。
2. 每个适配器的产出写进 `source_yield` 表：人物、来源、文档数、有效主张数、耗时、搜索次数。按需分析按历史产出率排序来源。
3. 长文本（字幕、电话会文字稿）先切块，只把含时间表述（年份、「明年」「by 2027」等）的块交给模型，控制成本。
4. 拿 003 里主张为 0 的 12 个人重跑（离线优先，搜索预算每人不超过 6 次），对比前后主张数。
