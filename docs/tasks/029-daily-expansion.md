# 029 每日扩库：用预算把「有分数的人」做多

负责人：Cursor
优先级：P0

## 目标

用户目标：近期多展示有分数的人物。用每天的 AFP 预算持续补数据，并量化进展。

## 背景

- 出分需要一个领域有足够多的已判定主张（见 `api/src/scoring/score.ts`）。现在多数人只有 0～5 条，所以没分。
- 名单：`data/batches/ai-tech-100.txt`；批量入口 `pnpm api:batch`；入队 `pnpm api:enqueue`。
- AFP 每日预算 3000（每次联网搜索 5 AFP），熔断和预算检查已有，不要绕过。

## 做法

1. **选谁补**：新脚本 `api/src/tools/expand-plan.ts` 每天生成当日计划，按「离出分最近」排序：某人某领域已判定条数离门槛差得越少越先补；其次是名单里还没收录的人。只读，输出计划。
2. **补什么**：对排在前面的人，优先补**已过期限、还没判定**的主张（到期核对，最快产出分数），其次才是发现新主张。
3. **执行**：`pnpm api:expand` = 生成计划 → 入队 → worker 跑到当日预算的 80% 停（留 20% 给网站上的按需分析）。可续跑。
4. **定时**：写成每天运行的说明（launchd 的 plist 放在 `deploy/` 下，不要自己加载；由用户决定是否启用）。
5. **进度指标**：每次运行结束在 `data/expansion/history.jsonl` 追加一行：日期、有分数的人数、有分数的领域数、公开主张数、已判定数、当日 AFP。首页的统计数字从接口取，不用改。

## 范围

- 新建 `api/src/tools/expand-plan.ts`、`api/src/tools/expand.ts`、`deploy/*.plist`、`data/expansion/`、`api/package.json`
- `api/src/jobs/*.ts` 只在需要「跑到预算百分比停止」时改
- 测试文件
