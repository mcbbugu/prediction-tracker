# 032 扩大人物名单，把每天的 AFP 用起来

负责人：Cursor
优先级：P0

## 目标

029 第一天只用了 375/3000 AFP 就没人可跑了，因为 `data/batches/ai-tech-100.txt` 基本已跑完。名单太短是现在增长的瓶颈。

## 做法

1. **新名单**，放在 `data/batches/`，每行一个人名（中文名加英文名，照现有格式），每个文件开头注释写选人标准：
   - `ai-tech-200.txt`：在 100 人基础上补 100 位 AI 与科技人物（芯片、云、机器人、自动驾驶、AI 实验室负责人、知名 AI 研究者）。
   - `investors-100.txt`：风投、对冲基金、知名分析师、经济学家（常做市场与宏观预测的）。
   - `crypto-50.txt`：加密行业创始人与评论者（预测多、可核查）。
   - `science-sports-culture-50.txt`：科学家、体育与文化界常做公开预测的人。
2. **选人标准**（遵守 SPEC「收录范围」）：
   - 只收公开身份人物，排除主要身份是政治人物的人。
   - 优先「常说带时间的预测或承诺」的人：先用模型从已有知识列候选，每人写一句「为什么会有可核查的预测」，再去掉不确定的人。
   - 已在库里的人不重复列。
3. **排序**：`expand-plan` 把名单里的新人排在「离出分最近」的老人物之后。新名单按文件顺序：ai-tech-200 → investors-100 → crypto-50 → 其他。
4. **跑**：用 `pnpm api:expand` 跑满当天预算的 80%，完成记录写当天前后对比（同 029 的表）。

## 范围

- 新建 `data/batches/*.txt`
- `api/src/tools/expand-plan.ts`（只在需要读多个名单时改）
- 不改其他代码

## 验收标准

- [x] 四个名单共 ≥ 300 个新人物，每人有一句理由（可放在同名 `.notes.md` 里）
- [ ] 跑完一天，AFP 用量接近 80%，完成记录贴前后对比表
- [x] 通用检查全部通过
