# 035 可信度接进每日扩库，新人物自动采集

负责人：Cursor
优先级：P1
依赖：034

## 目标

以后新收录的人物和已有人物都能自动补可信度对照，不靠手工写 JSON。

## 做法

1. **采集 agent**（`api/src/consistency/collect.ts`）：照 `data/consistency/README.md` 的规则，流程如下。
   - **列话题**：先列这个人最有代表性的 5～10 个建议和明确立场。列的时候还不知道结果，不准只挑「看起来会翻车的」。提示词里要明确写这一条，并在任务事件里记录列出的话题和理由。
   - **逐个查**：每个话题找后来的说法或本人行动，产出 `reversal`、`reaffirm`、`walk` 三类之一，找不到就记 `no_counterpart`。
   - 排除选举和政府政策相关的立场，排除带期限的预测（那类进兑现率）。
   - 所有原话走现有的存档和逐字核对，核对不过就丢弃并记原因。
   - 搜索复用 013 的多源发现，优先找不花 AFP 的来源。每人每次最多 8 次联网搜索。
2. **接进按需分析**：`discover.ts` 在利益关系之后加一步「可信度对照」，照常 emit 事件，任务页能看到列了哪些话题、各自找到了什么、丢弃了什么。
3. **接进每日扩库**：`expand-plan` 增加一类工作「补可信度」。优先补「已有兑现率分数、但可信度对照少于 5 条」的人，因为补到 5 条就能出分。预算规则不变（每天跑到 80% 停）。
4. 入库和计分复用 034 的逻辑；`data/expansion/history.jsonl` 增加一项「有可信度分的人数」。
5. **防偏差检查**：每次运行后统计「一致」所占比例。某人一次采集出来的对照全是「不一致」时，在事件里标出提醒，因为这往往说明列话题时挑了会翻车的。

## 范围

- 新建 `api/src/consistency/collect.ts`、`api/src/claims/discover.ts`（加一步）、`api/src/tools/expand-plan.ts`、`api/src/tools/expand.ts`、`api/src/jobs/*.ts`（如需新任务类型）
- 任务页展示新步骤（沿用 006 的组件）
- 测试文件

## 验收标准

- [ ] 对 3 个尚无可信度数据的人跑一遍，完成记录贴出列出的话题、产出的对照，以及一致和不一致各占多少
- [ ] 跑一次每日扩库，完成记录写有可信度分的人数前后对比
- [ ] 通用检查全部通过
